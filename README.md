# Конвертер валют

## Логика:

Объект enum CharCode содержит список валют. Валюты из ЦБ запрашиваются только
те, которые есть в этом списке, чтобы не загружать слишком много. Так же этот
объект является полем для объекта Money. Money передается в post запросе для
конвертации валюты. Поля: enum CharCode и BigDecimal amount (сумма валюты).

В Money enum работает как валидатор - если передается что-то, чего нет в списке
валют, вызов до метода convert() не доходит. Глобальный обработчик ошибок
отлавливает эту ситуацию. Плюс тут же отлавливается "если сумма валюты не
число".

В самом методе конвертации отлавливается ситуация если сумма валюты меньше или
ровна нулю.

В приложении всего два метода:

- integration/Integration.externalRequest(): get-запрос, можно вызвать для
  загрузки валют из ЦБ.
- service/CurrServiceImpl.convert(): post-запрос, вызывается для конвертации,
  после того как загружен список валют в БД. Если выполняется запрос на
  конвертацию, указанная валюта есть в списке перечисления CharCode, но валюты
  в БД не загружались, выполняется запрос на загрузку валют в БД.

```java
    CurrEntity curr = currRepo
        .findByCharCode(moneyCharCode)
        .orElseGet(() -> {
            log.info("Валюта есть в enum, но в БД еще не загружена");
            integration.externalRequest();
            return currRepo.findByCharCode(moneyCharCode).orElseThrow(() ->
                    new IllegalArgumentException(
                            "После загрузки курсов валюта не была найдена"
                    )
            );
        });

```

## Тесты

Тесты написаны для случаев:

- конвертации валюты с валидными полями: валюта есть в списке перечисления
  CharCode и сумма больше нуля.
- конвертации валюты с суммой меньше либо равной нулю.
- конвертации валюты с номиналом больше 1. У некоторых валют курс указан не за 1
  единицу а за 10, 100 или больше.

В юнит тестах не протестированы две ситуации, перехватываемые глобальным
обработчиком ошибок: "не корректный код валюты" и "сумма валюты не число". Они
отрабатываются еще до вызова метода конвертации, поэтому протестироваться могут
в интеграционных тестах.
